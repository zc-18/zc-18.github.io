Middleware

一、定义

中间件，这是一个听起来很高大上的名字

业内提起中间件，会有俩种含义吧

1.架构层面-传统含义

在java世界里，提到中间件，基本上都指的是类似于redis、xxl-job等独立部署的基础软件

它们意思是指一个单独的进程，通过网络进行通信，夹在应用与应用之间

大概在java的世界中，可以用下面这张图片来理解

2.代码层面-管道含义

为什么会说是管道含义，意指的是

把处理过程想象成一条管道，middleware 是管道上的一个个”阀门”

所以也很容易明白，在java世界中，代码层面的中间件意思就是类如切面编程呢个、过滤器等处理环节吧

大概一些实现形式如下

也就是说指得是请求处理链上的拦截环节

同时，这种说法也主要常见于 Express、Koa、ASP.NET Core 等生态

二、langchain

langchain中的Middleware沿用的是第二层含义，也就是指处理链路上的拦截环节

1.hook

想要搞懂langchain中的中间件，需要先明白langchain为agent调用所预留的hook钩子

Wrap 式钩子，也就是环绕型

他的意思就是包裹每次模型或者工具的调用

和其他四个不同，它会直接将整个过程包起来，类似于反射的实现

类似于这样，重要的就是可以直接在内部调用其内部方法直接向deepseek的服务端发起请求

before_agent与before_model

2.Middleware

对于Middleware，他其实就是指一个可复用、可插拔的功能单元，把一个完整能力打包起来

通俗讲 middleware 是”零件”，hook 是零件能接入的”插槽”

就像下图所示

除此之外，Middleware还可以带参数等，构造时传参数，比如重试次数

这个对比就非常不错

middleware hook
是什么 完整的功能单元 循环里可介入的时间点
数量 无限多，自己写或用内置 固定几个
类比 Java 里的某个 Filter 类 doFilter() 这个方法
例子 ModelRetryMiddleware wrap_model_call

四、自定义中间件

当预定义中间件不能够满足我们的需求时，需要自定义中间件

本质就是在之前提到的hook上自定义中间件

同时，hook也分为俩类

维度 节点式 Node-style 包装式 Wrap-style
包含的 Hook before_agent、before_model、after_model、after_agent wrap_model_call、wrap_tool_call
触发方式 到达某个节点时顺序执行 把整个调用包在里面
核心能力 读写 state 控制是否调用、调用几次
入参 (state, runtime) (request, handler)
返回值 None 或 state 更新的 dict handler 的返回结果
类比 路口的检查站 一层外壳

1.节点式

节点式钩子的自定义中间件比较容易理解

伪造一个需求：统计模型调用次数

明显需要在每次模型调用之后增加记录变量

参数

注解@after_model，这个注解代表langchain帮我们直接讲中间件定义到hook上

入参state、runtime，这俩参数为固定格式

返回值，返回值代表要修改seate的字典

中间件方式实现模型调用次数统计，可以实现模型无感知情况下统计数量

自定义的 CustomAgentState 必须通过 middleware 声明，同时也没必要在创建agent时声明

2.环绕式

第二类环绕式中间件比较复杂

定义需求：定义一个可以在调用模型时失败重试的中间件，最大重试次数为3次

3.拓展类定义中间件

上面都是通过注解的形式定义中间件，会比较散

langchain提供了一种通过拓展预定义类AgentMiddleware的形式自定义中间件

直接覆写父类的抽象方法即可

创建agent的时候直接传入中间件类参数即可

五、核心能力

这里介绍一些中间件可以实现的更加高级的功能

1.修改请求参数

这个主要是环绕型钩子函数用到

整体流程如上

本质就是用request.override(model_settings=...)重写请求参数

伪需求：根据context中用户的选择来开启或关闭模型的思考模式

request变量中存储runtime

用户可以通过state存储变量，实现动态控制模型思考

另外，还可以修改下面参数

字段 作用 典型场景
model 本次调用使用的模型 简单问题用小模型，复杂问题用大模型
messages 发给模型的消息列表 裁剪历史、摘要压缩、注入上下文
system_prompt 系统提示词 按用户角色、语言动态切换提示词
tools 本次可用的工具 按权限或场景动态过滤工具
tool_choice 工具选择策略 强制调用某个工具，或禁止调用
response_format 结构化输出格式 动态指定 Pydantic 输出模型
model_settings 额外模型参数 temperature、extra_body、开关思考模式

具体可以在官方文档可以找到
