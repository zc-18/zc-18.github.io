SpringBoot框架

  • 静态资源：服务器上存储的不会改变的数据，通常不会根据用户的请求而变化。比如：HTML、CSS、JS、图片、视频等(负责页面展示)

  • 服务器端根据用户请求和其他数据动态生成的，内容可能会在每次请求时都发生变化。比如：springboot等(负责逻辑处理)

  • Servlet、JSP等处理方式早已过期，目前都是springboot

2.具体剖析

  • 请求头具体代表内容

    • Host 请求的主机名
      User-Agent 浏览器版本，例如Chrome浏览器的标识类似Mozilla/5.0 … Chrome/79，IE浏览器的标识类似Mozilla/5.0 (Windows NT …) like Gecko
      Accept *表示浏览器能接收的资源类型，如text/，image/或者/表示所有；*
      AcceptLanguage 表示浏览器偏好的语言，服务器可以据此返回不同语言的网页；
      AcceptEncoding 表示浏览器可以支持的压缩类型，例如gzip, deflate等。
      Content-Type 请求主体的数据类型。
      Content-Length 请求主体的大小（单位：字节）。

    • 请求体

      • 距离请求头需要空一行

4.响应数据

  • 响应状态码

    • 一共有五大类状态码

    • 重要的为

    • 200 客户端请求成功。
      404 请求资源不存在，URL输入有误，或者网站资源被删除了。
      500 服务器发生不可预期的错误。

  • 具体请求头含义

5.服务器操作响应数据

  • 已经包装到HttpServletResponse类对象中

  • 一共有俩种方式

    • 利用HttpServletResponse类对象

    • @RestController
public class Response {
    @RequestMapping("/response")
    public void testResponse(HttpServletResponse response) throws IOException {
        //设置状态码
        response.setStatus(HttpServletResponse.SC_OK);
        //设置响应头
        response.setHeader("Content-Type","text/html;charset=utf-8");
        //设置响应体
        response.getWriter().write("<h1>Hello World!</h1>");
    }
}

4.IOC详解

  • ioc详细

    • 三层架构分别对应

      • 他们底层原本就封装了一层component注解

  • ​ 可以通过监控面板详细查看到有多少bean

    • @Component("userD    ao")

5.DI详解

  • 基于@Autowired注解进行依赖注入一共实现由三种方式

    • 属性注入

      • public class Serviceimpl implements userservice {
    @Autowired
    public userdaoimpl userdao ;

      • 如果只有一个构造函数，那@Autowired可以省略

    • .setter方法注入

      • @Autowired
public void setUserdao(userdaoimpl userdao) {
    this.userdao = userdao;
}

      • 保持类的封装性

  • 默认是按照类型注解

    • 如果注入时有多个类，会报错
    • 解决方案
      • @Primary
      • @Qualifier
      • @Resource
        • 他是按照名称注入，Autowired时按照类型注入
